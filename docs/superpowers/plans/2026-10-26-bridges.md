# Bridges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Bridges, a daily + practice Hashiwokakero page (`bridges.html`): join numbered islands with straight bridges (at most two per pair, no crossings) so every island's number is met and all islands connect.

**Architecture:** Same shape as Balanced and Patches: pure, DOM-free `bridges/{types,geometry,solver,generate,game,input}` modules, an SVG renderer `bridges/board`, and `bridges/app` wiring routes, HUD, win card, storage and analytics. Puzzles are generated deterministically by growing a bridge network on the grid and are accepted only when the range-based deduction solver reproduces it. The dashboard gains a registry entry.

**Tech Stack:** TypeScript, Vite (multi-page), Vitest (+ jsdom), Playwright. No UI framework.

**Spec:** `docs/superpowers/specs/2026-10-26-bridges-design.md`

## Global Constraints

- Create branch `feat/bridges` from `main` before Task 1 (the spec and this plan are already on `main`). Never `git push`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No new dependencies.
- Cells are flat indices `r * size + c`. Islands are sorted by cell; links sorted by `(a, b)` with `a < b`. `Count` is `0 | 1 | 2`.
- Presets: `small` 7×7 islands 10–13, `medium` 9×9 islands 17–22 (default + daily), `large` 11×11 islands 26–32; extra-link chance 0.25; bridge count 1 at 60 %, 2 at 40 %. Sizes outside 7–11 throw.
- Daily seed: `seedFromString('bridges-daily:' + isoDate)`.
- No lives, no attempts. Win = every island total equals its number and the network is connected. The board is never compared with the solution during play.
- Colours: satisfied island `#4fd6c3`, rule-break red `#ff5c7a`.
- Cell size `clamp(28px, fit, 56px)`; 11×11 fits 375 px wide; the page never scrolls horizontally.
- All `localStorage` access in try/catch; the game works without storage.
- Copy: tagline "Connect every island. Match every number."; win title "All connected"; dashboard done word "Solved".
- Animations off under `prefers-reduced-motion`.
- `bridges.html` copies `balanced.html` verbatim apart from title and entry (favicon and analytics script included).
- Run `npm test` and `npx tsc --noEmit` before each commit.

## Review Focus

1. A tap that hits no link (open water, or on an island) and a refused crossing both push no history, so Undo then reverts the previous real move. (Task 4 `refused crossing pushes nothing`; Task 5 `tap off every link does nothing`.)
2. A drag that returns to its start island, leaves the board, or is cancelled (`pointercancel`) adds no bridge. (Task 5 `drag back, off-board and cancel add nothing`.)
3. Satisfied-but-split is never a win, and `split` stays empty while any island is unsatisfied, so the red pulse doesn't fire mid-play. (Task 4 `split only when every island is satisfied`.)
4. A daily save with a crossing pair in use, the wrong length or bad characters starts a fresh board instead of crashing; a tab never overwrites a solved save from another tab. (Task 4 `restore rejects`; Task 7 `daily ignores a corrupt save`, `persist never overwrites a solved save from another tab`.)
5. Hand-edited hash `#/practice?preset=bogus&seed=abc` → Medium, random seed, no crash. (Task 7 `parseBridgesRoute`.)

**Files:**
- Create: `src/bridges/generate.ts`
- Test: `tests/bridges/generate.test.ts`

**Interfaces:**
- Consumes: Tasks 1–2; `mulberry32`, `seedFromString`, `randInt`, `shuffle` from `src/core/rng.ts`.
- Produces:
  - `PRESETS: Record<PresetId, { size: number; label: string; minIslands: number; maxIslands: number }>` — `small` `{7, 'Small', 10, 13}`, `medium` `{9, 'Medium', 17, 22}`, `large` `{11, 'Large', 26, 32}`. Sizes 8 and 10 use `round(0.21·size²)`–`round(0.265·size²)`.
  - `EXTRA_LINK = 0.25`, `DAILY_PRESET: PresetId = 'medium'`
  - `bridgesDailySeed(isoDate: string): number`
  - `generatePuzzle(size: number, seed: number): Puzzle` — deterministic per `(size, seed)`; one `mulberry32(seed)` drives everything.

**Algorithm** (spec §4):
```
generatePuzzle(size, seed):
  throw if size < 7 or > 11
  rng = mulberry32(seed); { minIslands, maxIslands } = params(size)
  repeat up to 300 times:
    islands = [random cell]; total = per island; laid = [] of {x, y, count}
    used = cell → 'island' | 'bridge'
    fails = 0
    while islands.length < maxIslands and fails < 200:
      x = random island with total < 8; dir = random; dist = 2 + randInt(rng, size)   // clipped: reject if off board
      path = cells strictly between x and target; target = cell at dist
      reject (fails++) when: target or any path cell is in `used`, or target is orthogonally next to an island
      place island y at target; count = min(rng() < 0.6 ? 1 : 2, 8 − total[x])
      lay {x, y, count}: mark path cells 'bridge', add count to both totals; fails = 0
      if rng() < EXTRA_LINK:
        for d in shuffle(other three directions of y):
          z = nearest island from y that way with no 'bridge' cell on the way (and ≥ 1 cell between); skip if none
          if total[y] < 8 and total[z] < 8: lay {y, z, min(rng() < 0.6 ? 1 : 2, 8 − total[y], 8 − total[z])}; break
    if islands.length < minIslands: continue
    numbers = totals; p = layout(size, islands with n)        // links include unused visible pairs
    solution = per link, the laid count between its islands, else 0
    if deepEqual(deduce(p), solution): return { ...p, solution }
  throw new Error('bridges: no puzzle')
```

### Task 5: Input state machine

**Files:**
- Create: `src/bridges/input.ts`
- Test: `tests/bridges/input.test.ts`

**Interfaces:**
- Consumes: Task 1 (`linkFrom`).
- Positions are in cell units: cell `(r, c)` spans `x ∈ [c, c+1)`, `y ∈ [r, r+1)`; its centre is `(c+0.5, r+0.5)`. The board converts pointer coordinates; off-board points are passed through unclamped.
- Produces:
  ```ts
  export const SLOP = 0.4; // cells: below this a press is a tap, at or above it a drag
  export type InputEvent =
    | { type: 'down'; x: number; y: number }
    | { type: 'move'; x: number; y: number }
    | { type: 'up' }
    | { type: 'cancel' };
  export type InputAction =
    | { kind: 'cycle'; link: number }
    | { kind: 'preview'; link: number }; // -1 clears the preview
  export type InputState = { mode: 'idle' | 'pressed' | 'drag'; island: number; x0: number; y0: number; link: number };
  export const initialInput: InputState;
  export function islandAt(p: Layout, x: number, y: number): number;  // island whose cell contains the point, else -1
  export function linkNear(p: Layout, x: number, y: number): number;  // link whose inner span contains the point along its axis and whose centre line is < 0.5 away; nearest wins, ties → lower index; else -1
  export function step(p: Layout, s: InputState, e: InputEvent): { state: InputState; action?: InputAction };
  ```
- Rules: `down` → `pressed` with `island = islandAt`. `move` beyond `SLOP` from `(x0, y0)`: from an island → `drag`, `link = linkFrom(island, dominant direction)`; from water → `drag` with `island -1` (a cancelled tap). While dragging from an island, back within `SLOP` of the island centre → `link -1`. Emit `preview` whenever `link` changes. `up`: `pressed` from water with `linkNear(x0, y0) ≥ 0` → `cycle`; `drag` with `link ≥ 0` → `cycle` plus `preview -1`; otherwise nothing (plus `preview -1` if one was shown). `cancel` → idle, `preview -1` if one was shown.
- Right-click is not part of the machine: the board calls `linkNear` on `contextmenu` and then `onRemove`.
