# Tangle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Tangle, a daily + practice arrow puzzle page (`tangle.html`), where tapping a snake-like arrow slides it off the board unless another arrow blocks it (costing one of 3 lives).

**Architecture:** Same shape as Mines: pure, DOM-free `tangle/{types,solver,generate,game}` modules, an SVG renderer `tangle/board`, and `tangle/app` wiring routes, HUD, end cards and storage. Levels are generated deterministically by reverse construction plus a solver-checked gap-fill pass. The dashboard gains a registry entry.

**Tech Stack:** TypeScript, Vite (multi-page), Vitest (+ jsdom), Playwright. No UI framework.

**Spec:** `docs/superpowers/specs/2026-10-21-tangle-design.md`

## Global Constraints

- Branch `feat/tangle` (already created, spec committed). Never `git push`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No new dependencies.
- Cells are flat indices `r * cols + c`; `Arrow.cells` is ordered tail → head; `Dir` 0 up, 1 right, 2 down, 3 left.
- Lives: 3. Presets: `medium` 30×30 maxLen 12 blockBias 1; `hard` 40×40 maxLen 14 blockBias 4 (default + daily); `huge` 50×50 maxLen 16 blockBias 4.
- Daily seed: `seedFromString('tangle-daily:' + isoDate)`.
- Arrow stroke width 26 % of a cell; arrowhead ≈ 42 % of a cell; colours from `ui/palette` `PALETTE`; bump flash `#ff5c7a`.
- Cell size `clamp(14px, fit, 28px)`; 40×40 must fit 1280×720 without page scroll; the page never scrolls horizontally.
- All `localStorage` access in try/catch; the game works without storage.
- Copy: tagline "Tap arrows out of the knot. Don't crash."; win title "Untangled ✦"; loss title "Out of lives"; dashboard lost label "Out of lives · attempt N"; Mines keeps "Boom · attempt N".
- Animations off under `prefers-reduced-motion`.
- Run `npm test` and `npx tsc --noEmit` before each commit.

## Review Focus

1. Tap on an empty gap cell (boards are ~97–99 % full, gaps exist) → nothing happens, no life lost. (Task 3 test `tap on an empty cell is ignored`.)
2. Double-tap / tap during an animation → the second tap is ignored; only one life can be lost per animation. (Task 5 test `taps are ignored while an animation plays`.)
3. A stale daily save — yesterday's, or with a `removed` length that no longer matches today's arrow count after a generator change — is discarded and a fresh board starts. (Task 3 `restore` tests + Task 6 test `daily ignores a save whose length does not match`.)
4. Two tabs on the same daily: a tab must not overwrite a won save or a later attempt. (Task 6 test `persist never overwrites a later attempt from another tab`.)
5. Hand-edited hash `#/practice?preset=bogus&seed=abc` → Hard preset, random seed, no crash. (Task 6 test in `parseTangleRoute`.)

  export type Level = { cols: number; rows: number; arrows: Arrow[] };
  export type LevelSpec = { cols: number; rows: number; maxLen: number; blockBias: number };

    | { kind: 'exit'; arrow: number; distance: number }
    | { kind: 'bump'; arrow: number; blocker: number; distance: number };

### Task 2: Generator

**Files:**
- Create: `src/tangle/generate.ts`
- Test: `tests/tangle/generate.test.ts`

**Interfaces:**
- Consumes: Task 1 types, `buildOcc`, `exitLine`, `analyze`; `mulberry32`, `seedFromString`, `randInt` from `src/core/rng.ts`.
- Produces:
  - `PRESETS: Record<PresetId, LevelSpec & { label: string }>` — labels `'Medium'`, `'Hard'`, `'Huge'`, values from Global Constraints.
  - `DAILY_PRESET: PresetId = 'hard'`
  - `tangleDailySeed(isoDate: string): number`
  - `generateLevel(spec: LevelSpec, seed: number): Level` — takes a numeric seed (not an `Rng`) because the quality gate retries with `seed + 1 … seed + 7`; still deterministic per `(spec, seed)`.
  - `fillRatio(level: Level): number` — covered cells / all cells.

**Algorithm** (spec §4; the prototype from brainstorming proved it):

```
attempt(spec, rng):
  occ = Int32Array(cols*rows).fill(-1); arrows = []
  fails = 0
  while fails < 30 * cols:
    best = null
    repeat spec.blockBias times:
      cand = drawCandidate(rng)        // null if rejected
      if cand and (best == null or crossings(cand) > crossings(best)): best = cand
    if best == null: fails++; continue
    fails = 0; commit(best)            // write occ, push arrow
  gapFill(rng); return level

drawCandidate:
  head = random empty cell; dir = randInt(4)
  reject if any exitLine cell is occupied, or the neck (head - DIRS[dir]) is out of bounds/occupied
  len = 3 + randInt(maxLen - 2); body = [head, neck]
  walk from the neck: options = empty, in-bounds, not in body, not in own exit line;
    keep going straight with probability 0.4 if allowed, else uniform option; stop when none
  cells = reverse(body)  // tail → head

crossings(cand) = number of distinct earlier arrows whose exit line contains a cell of cand

colour: randInt(9); redraw once if equal to the colour of an orthogonally adjacent arrow

gapFill (≤ 6 passes, stop when a pass changes nothing; empty cells visited in shuffled order):
  (a) for each neighbour arrow whose tail is adjacent to c and whose exitLine excludes c:
        prepend c; keep if analyze(level) != null else undo
  (b) else for each empty neighbour n, for both orders (tail,head) ∈ {(c,n),(n,c)}:
        dir = direction tail→head; add arrow; keep if analyze != null else undo

generateLevel(spec, seed):
  for k in 0..7: L = attempt(spec, mulberry32(seed + k))
    if spec.blockBias == 1 or (fillRatio(L) >= 0.95 and analyze(L).initiallyFree <= 0.2 * arrows): return L
    track best by (fill, -initiallyFree)
  return best
  throw if cols < 4 or rows < 4
```

If `hard` exceeds 150 ms in Step 4, optimise `analyze` usage in gap fill before anything else (e.g. reject (a)/(b) early when the new cell is not on any exit line and the extended arrow's line is unchanged — such a change cannot create a cycle; only call `analyze` otherwise).
