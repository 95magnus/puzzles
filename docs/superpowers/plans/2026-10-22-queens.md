# Queens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Queens, a daily + practice region-logic puzzle page (`queens.html`): place one queen per row, column and coloured region, with no two queens touching.

**Architecture:** Same shape as Mines and Tangle: pure, DOM-free `queens/{types,solver,generate,game,input}` modules, a DOM-grid renderer `queens/board`, and `queens/app` wiring routes, HUD, win card and storage. Puzzles are generated deterministically (random non-touching queens → grown regions → accept only if the bitmask solver counts exactly one solution). The dashboard gains a registry entry.

**Tech Stack:** TypeScript, Vite (multi-page), Vitest (+ jsdom), Playwright. No UI framework.

**Spec:** `docs/superpowers/specs/2026-10-22-queens-design.md`

## Global Constraints

- Branch `feat/queens` cut from `main`; commit the spec and this plan as its first commit. Never `git push`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No new dependencies.
- Cells are flat indices `r * size + c`; `Mark` 0 empty, 1 ✕, 2 queen; region id = `PALETTE` index (0..size-1).
- Presets: `small` 7×7, `medium` 8×8 (default + daily), `large` 9×9. Sizes outside 4–9 throw.
- Daily seed: `seedFromString('queens-daily:' + isoDate)`.
- No lives, no attempts. Win = `size` queens, no conflicts.
- Region tint: `PALETTE[region]` at ~35 % over the board background; 3 px region borders; conflict colour `#ff5c7a`.
- Cell size `clamp(32px, fit, 56px)`; 9×9 fits 375 px wide; the page never scrolls horizontally.
- All `localStorage` access in try/catch; the game works without storage.
- Copy: tagline "One queen per row, column and colour."; win title "Crowned ♛"; dashboard done word "Solved".
- Animations off under `prefers-reduced-motion`.
- Run `npm test` and `npx tsc --noEmit` before each commit.

## Review Focus

1. A drag that starts on a queen, or whose first cells are already ✕, must still undo as one step and must not merge into the previous tap's move. (Task 3 test `paint merges by gesture id, not by position in history`.)
2. A drag that leaves the board and comes back keeps painting; leaving never places a queen and `up` off-board ends the drag without a tap. (Task 4 test `move off the board is ignored; up ends the drag without a tap`.)
3. A player places a clashing queen, then removes the other one — the remaining queen must stop being red. Conflicts are recomputed, not accumulated. (Task 3 test `conflicts clear when the clashing queen goes`.)
4. Two tabs on the same daily: a tab must not overwrite a solved save. (Task 7 test `persist never overwrites a solved save from another tab`.)
5. Hand-edited hash `#/practice?preset=bogus&seed=abc` → Medium, random seed, no crash. (Task 7 test in `parseQueensRoute`.)

### Task 2: Generator

**Files:**
- Create: `src/queens/generate.ts`
- Test: `tests/queens/generate.test.ts`

**Interfaces:**
- Consumes: Task 1 types, `countSolutions`, `solve`, `isValidPlacement`; `mulberry32`, `seedFromString`, `randInt`, `shuffle` from `src/core/rng.ts`.
- Produces:
  - `PRESETS: Record<PresetId, { size: number; label: string }>` — `small` 7 `'Small'`, `medium` 8 `'Medium'`, `large` 9 `'Large'`.
  - `DAILY_PRESET: PresetId = 'medium'`
  - `queensDailySeed(isoDate: string): number`
  - `generatePuzzle(size: number, seed: number): Puzzle` — deterministic per `(size, seed)`; one `mulberry32(seed)` drives all attempts.
  - `regionSizes(p: Puzzle): number[]` and `isConnected(p: Puzzle, region: number): boolean` — exported for tests.

**Algorithm** (spec §4):
```
generatePuzzle(size, seed):
  throw if size < 4 or size > 9
  rng = mulberry32(seed)
  repeat up to 2000 times:
    cols = randomQueens(size, rng)               // backtracking, columns tried in shuffled order, |cols[r]-cols[r-1]| >= 2
    ids = shuffle(rng, [0..size-1])              // region id of the queen in row r = ids[r]
    regions = Uint8Array(size*size).fill(255); regions[r*size+cols[r]] = ids[r]
    frontier per region = unassigned orthogonal neighbours of its cells
    while unassigned cells remain:
      pick region k with probability ∝ 1 / (size of k)^2 among regions whose frontier is non-empty
      give k a uniformly random frontier cell
    if count(regionSizes == 1) > 1: continue
    p = { size, regions, solution: cols }
    if countSolutions(p, 2) == 1: return p
  throw new Error('queens: no unique puzzle')
```
`solution` is `cols` (it is valid by construction; uniqueness makes it *the* solution).

If `large` exceeds 100 ms in Step 4, add the repair step from spec §4 (when the count is 2, move one cell of the second solution's offending queen into a neighbouring region that keeps both regions connected, then recount) before anything else.

### Task 3: Game state

**Files:**
- Create: `src/queens/game.ts`
- Test: `tests/queens/game.test.ts`

**Interfaces:**
- Consumes: Task 1 types; `pz`, `UNIQUE4` from `tests/queens/helpers.ts`.
- Produces (all mutate `s` and return the changed cells; all return `[]` once `s.status === 'won'`):
  - `newGame(p: Puzzle): GameState`
  - `cycle(s: GameState, cell: number): number[]` — 0 → 1 → 2 → 0; pushes `{ cells: [cell], before: [old] }` (no gesture); then sets `won` if `isWin(s)`.
  - `paint(s: GameState, cells: number[], to: 0 | 1, gesture: number): number[]` — spec §6; skips queens and cells already `to`; merges into the last move iff `history.at(-1)?.gesture === gesture`. Never wins (queens are untouched).
  - `undo(s: GameState): number[]`
  - `clear(s: GameState): number[]` — every non-empty cell → 0 as one move; `[]` and no move when the board is already empty.
  - `conflicts(s: GameState): Set<number>` — computed from the current queens every call.
  - `queenCount(s: GameState): number`
  - `isWin(s: GameState): boolean`
  - `encode(s: GameState): string` — `'0' | '1' | '2'` per cell.
  - `restore(p: Puzzle, cells: string): GameState | null` — `null` if length ≠ `size²` or any char outside `[012]`; empty history; status from `isWin`.

  - `encode/restore round trip` with queens and marks; `restore` of the solution string → `won`.

### Task 4: Input state machine

**Files:**
- Create: `src/queens/input.ts`
- Test: `tests/queens/input.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type InputEvent =
    | { type: 'down'; cell: number; mark: Mark }   // mark = current Mark of that cell
    | { type: 'move'; cell: number | null }        // null = off the board
    | { type: 'up' }
    | { type: 'cancel' };
  export type InputAction =
    | { kind: 'tap'; cell: number }
    | { kind: 'paint'; cells: number[]; to: 0 | 1; gesture: number };
  export type InputState = { mode: 'idle' | 'pressed' | 'drag'; start: number; last: number; to: 0 | 1; gesture: number };
  export const initialInput: InputState;
  export function step(s: InputState, e: InputEvent): { state: InputState; action?: InputAction };
  ```
- Rules (spec §7): `down` → `pressed`, `gesture + 1`, `to` = `mark === 1 ? 0 : 1`. `move` to a cell ≠ `last` while pressed → `drag`, action `paint` with `[start, cell]`; while dragging → `paint` with `[cell]`; same cell or `null` → no action. `up` while pressed → `tap(start)`; while dragging → no action; both → `idle`. `cancel` → `idle`, no action. Events in the wrong mode are ignored.

  - `drag erases from a ✕ start`: down(3, 1), move(4) → `to 0`.
  - `drag from a queen paints ✕`: down(3, 2), move(4) → `to 1` (the game skips the queen).
  - `re-entering the start cell keeps the drag`: down(3,0), move(4), move(3) → `paint [3]`, mode still `drag`.
  - `move off the board is ignored; up ends the drag without a tap`: down(3,0), move(null) → no action, still `pressed`; move(4) → `paint`; move(null); up → no action, `idle`.
  - `each gesture gets a new id`: two taps → gestures differ.
  - `cancel drops the gesture`.
